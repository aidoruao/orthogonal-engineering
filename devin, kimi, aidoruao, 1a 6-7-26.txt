## Implementation Path (No Server Required)

**Step 1:** Create `game/index.html` at repo root. It loads Pyodide from CDN.

**Step 2:** Pyodide mounts the repo filesystem via `pyodide.http` or by running in the same directory (if served via `python -m http.server` locally).

**Step 3:** The game imports your actual modules:
- `from yeshua_scanner import scan_for_stubs`
- `from yeshua_agent import verify_citizenship`
- `from repair_loop import identify_gaps`

**Step 4:** The skill tree is a visual map of your 8 categories. Each node is a directory. The color is determined by running the warden on that directory in real-time.

**Step 5:** Player's `localStorage` stores which domains they've verified. But the **truth** is always in the repo. If the player deletes their browser cache, they can re-verify and the warden will confirm the same results.

---

## The One Critical Rule

**The game cannot generate fake data. Ever.**

If the game needs to show "what is a stub?", it finds a real stub in the repo. If it needs to show "what is a valid ProofObject?", it finds a real one in `evidence/` or `documentation/`. If the repo changes, the game changes. The game is a **read-only viewer and a write-through verifier** — not a separate universe.

That's the difference between a toy and a **production-grade warden interface**."
