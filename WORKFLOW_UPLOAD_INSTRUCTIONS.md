## For GitHub Copilot: How to Handle YML Permissions

### Understanding the Permission Model

GitHub separates repository content permissions from workflow permissions:

| Scope | Can Modify | Cannot Modify |
|-------|-----------|---------------|
| `repo` | Regular files, docs, code | `.github/workflows/*.yml` |
| `workflow` | Everything including workflows | Nothing (full access) |

### Recommended Approach for GitHub Copilot

#### Option 1: Use GitHub UI (Recommended for Safety)

When Copilot needs to create workflow files:

1. **Generate the file content** in the conversation
2. **Present to user** with clear instructions
3. **User uploads** via GitHub UI at:
   - `https://github.com/{owner}/{repo}/blob/main/.github/workflows/`
   - Click "Add file" → "Create new file"
4. **Copilot verifies** by checking if workflow appears in Actions tab

#### Option 2: Use GitHub CLI (If Available)

If the environment has `gh` CLI with proper authentication:

```bash
# Check if gh CLI is available and authenticated
gh auth status

# Create workflow file via API
gh api repos/{owner}/{repo}/contents/.github/workflows/{name}.yml \
  --method PUT \
  --input - <<EOF
{
  "message": "Add workflow",
  "content": "$(base64 -w 0 < workflow.yml)"
}
EOF
```

#### Option 3: Document and Delegate (Current Approach)

When workflow permissions are not available:

1. **Create files locally** in a temporary location
2. **Document the limitation** clearly (as done here)
3. **Provide upload instructions** for human or other AI with appropriate access
4. **Continue with other tasks** that don't require workflow permissions

### Best Practices for GitHub Copilot

1. **Always check permissions first:**
   ```bash
   # Test if workflow modifications are allowed
   git push origin main 2>&1 | grep -i "workflow"
   ```

2. **Separate workflow commits from regular commits:**
   - Regular commits: Pushed immediately
   - Workflow commits: Saved locally with documentation

3. **Provide clear handoff documentation:**
   - What files need to be uploaded
   - Where they should go
   - What configuration is needed (secrets, labels)
   - How to test

4. **Use the `.github/labels.yml` pattern:**
   - Create documentation of required labels
   - Note that labels must be created via UI
   - Don't fail if labels don't exist yet

### Token Scope Requirements Reference

```yaml
# Minimum required for code commits
scopes: repo

# Required for workflow modifications  
scopes: repo, workflow

# Full access including secrets
scopes: repo, workflow, admin:repo_hook
```

### Testing Workflow Without Push

To verify workflow syntax before upload:

```bash
# Validate YAML syntax
python3 -c "import yaml; yaml.safe_load(open('.github/workflows/workflow.yml'))"

# Use GitHub's workflow schema validation (requires gh CLI)
gh workflow run workflow-name.yml --dry-run
```
