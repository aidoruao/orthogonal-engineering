Section 2

Anonymous Filing Infrastructure: Kill the Death Asymmetry

THE DEATH ASYMMETRY: Suchir Balaji is dead. The mechanism that killed him — or allowed his death to go uninvestigated — is identification. If the whistleblower is known, they can be targeted. If the evidence is centralized, it can be seized. If the filing is traceable, it can be intercepted. v7 eliminates identification, centralization, and traceability.

Tor Hidden Service Filing

Route: Whistleblower -> Tor -> Agency Portal

Mechanism: Headless browser (Playwright/Selenium) operated via Tor circuit. Each filing uses a fresh exit node. No IP logging. No session fingerprinting.

Agency Support: SEC TCR (via attorney proxy), NLRB e-file, FTC reportfraud, CA DLSE online, EU DPA web forms

Anonymity: Full — agency sees only Tor exit IP

Automation: Python script + Tor proxy + Playwright

Blockchain Evidence Timestamping

Chain: Bitcoin / Ethereum / Arweave

Mechanism: SHA-256 hash of evidence file published to blockchain. Timestamp is immutable and globally verifiable. Original file stays local. Only hash is public.

Cost: ~$0.50 per hash (Bitcoin OP_RETURN) or $0 (Arweave with bundlr)

Verification: Anyone can verify file integrity by re-hashing and comparing to chain

Anonymity: Full — hash reveals nothing about content

Automation: Python script + web3.py + local wallet

IPFS Evidence Replication

Network: InterPlanetary File System

Mechanism: Evidence files encrypted with AES-256, uploaded to IPFS. CID (content identifier) distributed to trusted nodes. Encryption key split via Shamir's Secret Sharing.

Redundancy: 5+ geographic nodes, no single point of failure

Retrieval: Any node with CID can reconstruct; key shards required for decryption

Anonymity: Full — IPFS is content-addressed, no location metadata

Automation: ipfs-cli + ssss (Shamir's Secret Sharing Scheme)

Dead Man's Switch

Trigger: Missed check-in + cryptographic time-lock

Mechanism: Whistleblower must check in every 24-72 hours. Missed check-in triggers automatic release of pre-configured evidence packages to pre-configured recipients (media, attorneys, regulators, public).

Time-Lock: Encrypted packages released via blockchain smart contract after timestamp + delay. No human intervention required.

Check-in Methods: Signal message, Tor hidden service ping, email with PGP signature, physical dead drop confirmation

Anonymity: Full — release is automated, no human knows trigger

Automation: Cron job + smart contract + Signal bot

Attorney Escrow for Evidence

Mechanism: Attorney-client privilege + encrypted vault

Process: Whistleblower encrypts evidence, sends to attorney via Signal/Session. Attorney holds in encrypted vault. Attorney cannot be compelled to disclose without court order.

Privilege: Work product doctrine + attorney-client privilege = strongest legal shield

Backup: Attorney vault + IPFS CID + blockchain hash = triple redundancy

Anonymity: Partial — attorney knows identity, but privilege protects

Automation: Signal auto-forward + encrypted vault sync

Anonymous Communication Channels

Primary: Signal / Session / SimpleX

Signal: E2E encrypted, phone number can be burner, disappearing messages, sealed sender

Session: No phone number required, onion routing, decentralized, no metadata

SimpleX: No identifiers, no server-side user list, double ratchet encryption

Backup: Tails OS live USB + public WiFi + disposable hardware

Anonymity: Full — no metadata, no identifiers, no server logs

Automation: Signal CLI bot + Session auto-responder

ANONYMOUS FILING WORKFLOW: End-to-End

Step 1: Evidence Collection (Local, offline)

  • Document everything on air-gapped machine or Tails OS live USB
  • Generate SHA-256 hash of each evidence file
  • Encrypt files with AES-256, split key via Shamir's Secret Sharing (3-of-5)

Step 2: Blockchain Timestamping (One-way, anonymous)

  • Publish hash to Bitcoin OP_RETURN or Arweave
  • Record transaction ID and block height
  • Verify on blockchain explorer (via Tor)

Step 3: IPFS Replication (Distributed, encrypted)

  • Upload encrypted files to IPFS, record CID
  • Distribute CID to 5+ trusted nodes (attorneys, journalists, activists)
  • Distribute key shards to 5+ trusted holders (no single holder has full key)

Step 4: Attorney Escrow (Privileged, protected)

  • Send encrypted evidence + CID + blockchain TX ID to attorney via Signal/Session
  • Attorney stores in encrypted vault, acknowledges receipt
  • Attorney prepares filing strategy without knowing full content (work product)

Step 5: Auto-Filing (Automated, Tor-routed)

  • Machine navigates agency portal via Tor circuit
  • Fills form with whistleblower-provided data (anonymized)
  • Uploads attachments (redacted, anonymized)
  • Confirms submission, captures confirmation number
  • Logs confirmation to encrypted local database

Step 6: Dead Man's Switch (Insurance, automated)

  • Configure release triggers: missed check-in, specific date, external event
  • Configure release recipients: media outlets, regulatory agencies, public archives
  • Configure release content: full evidence, redacted summary, or specific documents
  • Test monthly with dummy data

Automated Scheduler: Follow-Up + Deadline Management

THE SCHEDULER ARCHITECTURE

Every filing has deadlines. Every complaint has follow-up dates. Every agency has response windows. The scheduler automates all of this: calendar invites, deadline alerts, auto-generated follow-up letters, status tracking dashboard. It integrates with the aggregation engine, the auto-filing bots, and the scraping network to create a closed-loop system where the machine never forgets, never misses a deadline, and never stops pushing.
