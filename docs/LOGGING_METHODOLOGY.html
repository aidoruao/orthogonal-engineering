LOGGING METHODOLOGY

Ontologically Correct Unicode Handling in Pipeline Systems

The Three-Layer Mismatch

Layer 1: Filesystem
Supports full Unicode filenames (≡, ƒÄ», emoji, etc.)
↓
Layer 2: Python 3.14
Internal UTF-8 processing (handles all Unicode)
↓
Layer 3: Windows Console (cp1252)
❌ Rejects non-Latin characters → UnicodeEncodeError

❌ The Category Error

When Python scripts use print() to output Unicode filenames, the Windows PowerShell console (cp1252 encoding) cannot render characters like:

  • ≡ (U+2261 - Identical To)
  • ƒÄ» (U+1D6FB - Mathematical Bold Small Phi)
  • 🤖 (U+1F916 - Robot Face)
  • ✅ (U+2705 - Check Mark)

Result: UnicodeEncodeError: 'charmap' codec can't encode character

Why Previous Solutions Were Inadequate

❌ Option 1: sys.stdout wrapper

sys.stdout = io.TextIOWrapper(
    sys.stdout.buffer, 
    encoding='utf-8'
)

Problem: Shell-dependent. Breaks if script is redirected, called by another process, or run in different environments.

❌ Option 2: Rename files

Problem: Destroys evidence. The Unicode characters (≡, ƒÄ») have semantic meaning in the methodology and removing them is data loss.

❌ Option 3: Silent character stripping

print(text.encode(
    'cp1252', 
    errors='ignore'
).decode('cp1252'))

Problem: Characters disappear silently. Information is lost permanently with no audit trail.

❌ Option 4: Console encoding change

subprocess.run(
    ['chcp', '65001'],
    shell=True
)

Problem: Modifies global system state. Affects other processes and requires administrator privileges in some environments.

✅ The Legitimate Solution: Separation of Concerns

Principle: Output Rendering ≠ Data Logging

Console display and data persistence are orthogonal concerns that should not share the same channel.

Implementation

# At top of ALL pipeline scripts
import logging

# Configure UTF-8 file logging
logging.basicConfig(
    filename='pipeline_run_log.txt',
    level=logging.INFO,
    encoding='utf-8',  # ← CRITICAL: Full Unicode support
    format='%(asctime)s - %(message)s'
)

# Replace all print() calls with logging
# OLD: print(f"Reading {filename}...")
# NEW: logging.info(f"Reading {filename}...")

# Console gets ASCII-safe status only
print("[SUCCESS] Script completed. See pipeline_run_log.txt")

What This Achieves

Console Output (cp1252)

[ANALYZING] orthogonal-engineering-main
[REPORT] 62 files analyzed
[SUCCESS] Analysis complete

Purpose: Real-time status for user

Log File (UTF-8)

2026-01-19 09:06:51 - Reading AGENT_IN_IDE.md
2026-01-19 09:06:51 - Reading ≡ƒÄ»_START_HERE.md
2026-01-19 09:06:51 - Results: {"depth_score_pct": 20.0}

Purpose: Complete audit trail with full Unicode

Why This Is Ontologically Correct

  1. Separates Concerns: Display layer ≠ Persistence layer
  2. Encoding is Explicit: UTF-8 declared once, applies forever
  3. Indefinite: Works regardless of console, shell, or OS
  4. Inspectable: Full Unicode preserved for audit and debugging
  5. Deterministic: Same input → same log output, always
  6. No State Mutation: Doesn't modify system console settings
  7. Fail-Safe: If logging fails, console still shows status
