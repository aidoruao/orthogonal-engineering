# Campaign Schema

Version: 1.0.0  
Standard: CAMPAIGN-SCHEMA-001  
Authority: Orthogonal Engineering  

This document defines the canonical structure for every campaign in the `campaigns/` directory. All campaigns must conform to this schema. Scope reduction is detected automatically by `scope_reduction_detector.py`.

---

## Campaign Markdown Specification

Every campaign definition file (`*.md`) must carry YAML frontmatter and the following sections.

### Required YAML Frontmatter

```yaml
---
tags: [campaigns, <domain>, <status>]
register: <register>
---
```

- `tags`: Must include `campaigns`. Additional tags describe domain and status.
- `register`: One of `technical`, `canonical`, `witness`, `governance`.

### Required Sections

| Section | Content |
|---|---|
| **Campaign ID** | Unique identifier, e.g. `CAMPAIGN-FORENSIC-OFFENSIVE-001` |
| **Authority** | Who authored / approved the campaign |
| **Date** | ISO-8601 date of canonization |
| **Predecessors** | List of campaign IDs this campaign builds upon |
| **Constraint Block** | Bullet list of invariants: 0 scope reduction, 0 floats, 0 stubs, 0 black boxes, 0 proprietary dependencies, every claim has `falsifies_if`, every function returns `Tuple[bool, ProofObject]` |
| **Parts Table** | One table per part: Deliverable / What / Est. LOC / Kimi Sessions |
| **Execution Model** | Directory tree showing where files live |
| **Anti-Crash Protocol** | Branch naming, commit pattern, forbidden actions (do not run `verify_all.py`, `auto_onboard.py`, etc.) |
| **Summary** | Total LOC estimate and session count |

## Campaign Spec JSON Specification

Every campaign must have a machine-readable companion `*_spec.json` file. The JSON schema is:

```json
{
  "campaign": "CAMPAIGN-ID-001",
  "description": "Short human-readable summary.",
  "expected_outputs": [
    {"path": "relative/path/from/repo/root", "type": "file", "stage": "A"},
    {"path": "relative/path/from/repo/root", "type": "directory", "stage": "B"}
  ]
}
```

### Field Rules

| Field | Type | Required | Notes |
|---|---|---|---|
| `campaign` | string | Yes | Must match the Campaign ID in the `.md` file |
| `description` | string | Yes | <= 280 characters |
| `expected_outputs` | array | Yes | Each item must have `path` and `type` |
| `path` | string | Yes | Relative to repo root; no leading `./` |
| `type` | string | Yes | `"file"` or `"directory"` |
| `stage` | string | No | Alphabetic stage label (e.g. `H`, `I`, `J`) |

### Verification

Run the scope-reduction detector against any spec:

```bash
python3 audit/scope_reduction_detector.py campaigns/<campaign>_spec.json
```

Exit code 0 means all expected outputs exist and are non-empty. Exit code 1 means scope reduction detected. The detector also writes `audit/SCOPE_REDUCTION_REPORT.json`.

## Campaign Lifecycle States

| State | Meaning |
|---|---|
| `PLANNED` | Spec exists but no files have been created |
| `IN_PROGRESS` | Some expected outputs delivered, scope reduction > 0 |
| `ACTIVE` | All expected outputs delivered for current scope; may expand |
| `ARCHIVED` | Campaign complete, no further work planned |
| `DEPRECATED` | Superseded by another campaign; do not use |

---

## Part-Level Specs

Large campaigns may be split into part-level spec JSONs under `campaigns/<campaign_dir>/partN_spec.json`. Each part spec uses the same schema as the top-level spec. The aggregate campaign auditor runs scope reduction against every spec recursively.

## Anti-Crash Protocol (Global)

```
BEFORE ANYTHING:
  python3 tools/agent_health_check.py --fast
  git checkout -b kimi/<campaign>-<part>

AFTER EACH PHASE:
  git add <files>
  git commit -m "feat(<campaign>): Part N Phase X -- <name>"
  git push origin kimi/<campaign>-<part>

DO NOT:
  - Run verify_all.py, standards_check.py --verify, or auto_onboard.py
  - Read session transcripts or .txt files
  - Enumerate directories with find/ls -R

IF CONTEXT > 40%:
  Stop. Commit. Push. New session.
```
